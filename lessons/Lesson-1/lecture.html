1. Проблема без React: почему «голый» JS ломается

1. The problem without React: why "raw" JS breaks

Вы уже умеете писать HTML, CSS и базовый JavaScript. И, возможно, думаете: «Зачем мне какой-то React, если я могу всё то же самое сделать через document.getElementById?» Справедливый вопрос. На нём и начнём — с боли, которую React решает.

Представьте простую задачу: счётчик. Кнопка +, кнопка -, и число на экране. Звучит элементарно. Но как только к счётчику добавляются ещё 10 таких же элементов на странице, связанных списков, форм — код быстро превращается в кашу. Проблема называется рассинхрон DOM и данных.

You already write HTML, CSS and basic JavaScript. And maybe you're thinking: "Why do I need some React if I can do all that with document.getElementById?" Fair question. Let's start right there — with the pain that React fixes.

Imagine a simple task: a counter. A + button, a - button, and a number on screen. Sounds trivial. But the moment you add 10 more such widgets, linked lists, forms — the code turns into soup. The problem is called DOM-and-data desynchronization.

Счётчик на «ванильном» JS:

Counter in "vanilla" JS:

<div id="counter">0</div>
<button id="plus">+</button>
<button id="minus">-</button>

<script>
    let count = 0;
    const counterEl = document.getElementById('counter');

    document.getElementById('plus').addEventListener('click', () => {
        count = count + 1;
        counterEl.textContent = count;   // <-- ручное обновление DOM
    });

    document.getElementById('minus').addEventListener('click', () => {
        count = count - 1;
        counterEl.textContent = count;   // <-- снова ручное обновление
    });
</script>

Видите проблему? Переменная count — это данные. А counterEl.textContent = count — это ручная синхронизация данных с экраном. Вы должны помнить обновить DOM каждый раз, когда меняются данные. Забыли? На экране старое число, а в коде — новое. Баг.

Представьте: 20 компонентов, 50 переменных. В какой-то момент вы забываете обновить один элемент, и всё приложение выглядит «как будто сломано». Это реальная боль. Именно поэтому к 2013 году Facebook создал React.

See the problem? The variable count is the data. And counterEl.textContent = count is manual sync between data and screen. You have to remember to update the DOM every time the data changes. Forgot once? Old number on screen, new number in code. Bug.

Imagine: 20 components, 50 variables. At some point you forget to update one element, and the whole app looks "broken". Real pain. That's exactly why Facebook built React in 2013.

Аналогия — ресторан без официанта. Представьте, что на кухне повара пишут меню, а вы — клиент — каждые 5 минут идёте на кухню, читаете что поменялось, и сами переписываете меню у себя на столе. Это «ванильный JS». Если забыли — сидите с неактуальной информацией. А React — это официант: повара меняют меню, официант автоматически приносит обновление на ваш стол. Вам думать не надо.

Analogy — restaurant with no waiter. Imagine the chefs update the menu in the kitchen, and you, the customer, walk to the kitchen every 5 minutes, read what's changed and rewrite the menu on your table yourself. That's "vanilla JS". Forgot? You sit with stale info. React is the waiter: chefs change the menu, the waiter automatically brings the update to your table. You don't have to think about it.

Тот же счётчик на React:

The same counter in React:

function Counter() {
    const [count, setCount] = React.useState(0);

    return (
        <div>
            <div>{count}</div>
            <button onClick={() => setCount(count + 1)}>+</button>
            <button onClick={() => setCount(count - 1)}>-</button>
        </div>
    );
}
Заметьте: нет getElementById, нет textContent = count. Вы просто описываете: «На экране должен быть {count}». Меняете count через setCount — экран обновляется сам. Это и есть главная идея React.
Notice: no getElementById, no textContent = count. You just describe: "There should be {count} on screen". Change count via setCount — the screen updates itself. That's React's core idea.

2. Что такое React на самом деле

2. What React really is

Короткое определение: React — это JavaScript-библиотека для построения пользовательских интерфейсов. Разберём по словам.

Short definition: React is a JavaScript library for building user interfaces. Let's break it down word by word.

СловоЧто это значит на практике
JavaScriptНе отдельный язык. Вы пишете на JS, но с дополнительными возможностями. Всё, что вы знаете о JS, работает в React.
БиблиотекаНе фреймворк. Маленький «инструмент», который вы добавляете в проект. Вы решаете, как организовать код.
Для построенияГотовых «страниц из коробки» нет. Вы конструируете из кубиков.
Пользовательских интерфейсовВсё, что видит пользователь: кнопки, формы, списки, меню, модалки, анимации.
WordPractical meaning
JavaScriptNot a separate language. You write in JS with extra abilities. Everything you know about JS works in React.
LibraryNot a framework. A small "tool" you add to a project. You decide how to organize the code.
For buildingNo ready-made "out-of-the-box" pages. You assemble from blocks.
User interfacesEverything the user sees: buttons, forms, lists, menus, modals, animations.

Историческая справка. React создал Джордан Уолке — инженер Facebook — в 2011 году. Первое применение — новостная лента Facebook.com. В 2013 году код открыли как open-source. Сегодня, в 2026-м, React поддерживают Meta и сообщество из 1500+ контрибьюторов. Текущая версия: 19.x.

Historical note. React was created by Jordan Walke — a Facebook engineer — in 2011. First deployed in the Facebook.com news feed. In 2013 the code was open-sourced. Today, in 2026, React is maintained by Meta and a community of 1,500+ contributors. Current version: 19.x.

React — не магия и не «новый JavaScript». Это обычный JS плюс две библиотеки (react и react-dom) плюс немного «синтаксического сахара» — JSX. Всё, что происходит внутри, можно написать руками. Просто было бы в 10 раз дольше.
React isn't magic and isn't "a new JavaScript". It's ordinary JS plus two libraries (react and react-dom) plus a bit of "syntactic sugar" — JSX. Everything that happens inside could be hand-written. It would just be 10× longer.

3. Компоненты — главная идея React

3. Components — React's main idea

Если запомнить одно слово из всего этого занятия, пусть это будет «компонент». Компоненты — это фундамент React. Всё остальное — детали.

Компонент — это самостоятельный кусок интерфейса, который можно использовать много раз. Кнопка — компонент. Карточка товара — компонент. Меню — компонент. Вся страница — тоже компонент, собранный из меньших.

If you remember one word from this whole lesson, let it be "component". Components are the foundation of React. Everything else is detail.

A component is a self-contained piece of UI you can reuse many times. A button is a component. A product card is a component. A menu is a component. The whole page is also a component, assembled from smaller ones.

LEGO. У вас есть кубики: «стена 2×4», «окно», «дверь», «колесо». Из одних и тех же кубиков вы собираете дом, машину, корабль. Компоненты в React — это те же кубики LEGO. Один раз создаёте кнопку — дальше используете её во всём приложении. Не нужно заново писать стили и поведение.

IKEA. В каталоге IKEA есть ящик Malm, стол Linnmon, стул Ivar. Из этих «компонентов» миллионы людей собирают уникальные комнаты. Никто не производит мебель с нуля. React устроен так же: собираете приложение из готовых и своих компонентов.

LEGO. You have bricks: "2×4 wall", "window", "door", "wheel". From the same bricks you build a house, a car, a ship. Components in React are those same LEGO bricks. You build a button once — then use it across the whole app. No need to re-write styles and behavior.

IKEA. The IKEA catalog has the Malm dresser, the Linnmon table, the Ivar chair. From these "components", millions of people build unique rooms. Nobody makes furniture from scratch. React is the same: you assemble the app from ready-made and your own components.

Страница Instagram как дерево компонентов: <App> ├── <Header/> (логотип, поиск, уведомления) ├── <Stories/> (истории сверху) │ └── <StoryCircle/> × 10 ├── <Feed/> (лента постов) │ └── <Post/> × N │ ├── <PostHeader/> │ ├── <PostImage/> │ ├── <PostActions/> (лайк, коммент, share) │ └── <PostCaption/> └── <Sidebar/> (предложения подписаться)
Instagram page as a component tree: <App> ├── <Header/> (logo, search, notifications) ├── <Stories/> (stories at the top) │ └── <StoryCircle/> × 10 ├── <Feed/> (post feed) │ └── <Post/> × N │ ├── <PostHeader/> │ ├── <PostImage/> │ ├── <PostActions/> (like, comment, share) │ └── <PostCaption/> └── <Sidebar/> (follow suggestions)

Что даёт компонентный подход:

What the component approach gives you:

  • Переиспользование. Написали <Button /> — используете 200 раз.
  • Изоляция. Сломалась одна карточка — остальные работают. Не влияют друг на друга.
  • Читаемость. Смотришь на <Header /> <Feed /> <Footer /> — и сразу понимаешь структуру страницы.
  • Работа в команде. Один разработчик пишет Header, другой — Feed, третий — Footer. Никто никому не мешает.
  • Тестируемость. Компонент можно проверить отдельно от всего приложения.
  • Reuse. Wrote <Button /> — used 200 times.
  • Isolation. One card broke — the rest still work. They don't affect each other.
  • Readability. Looking at <Header /> <Feed /> <Footer /> — you immediately see the page structure.
  • Teamwork. One dev writes Header, another writes Feed, a third writes Footer. Nobody blocks anybody.
  • Testability. You can test a component separately from the whole app.

На собеседовании на позицию junior-разработчика 80% вопросов по React крутятся вокруг компонентов: «что такое компонент», «как передать данные в компонент», «как сделать переиспользуемый компонент». Поймёте компоненты глубоко — половина собеседования позади.

In a junior React interview, 80% of React questions are about components: "what is a component", "how do you pass data into a component", "how do you make a reusable component". Understand components deeply — half the interview is already behind you.

4. Виртуальный DOM простыми словами

4. Virtual DOM in plain words

Термин, который вы услышите на любом React-собеседовании. На первом занятии не обязательно разбираться в деталях — достаточно понимать на уровне аналогии. На уроке 18 мы вернёмся к этому глубже.

A term you'll hear at any React interview. On lesson 1 you don't need the details — just an analogy-level understanding. We'll come back deeper on lesson 18.

Черновик и чистовик. Когда вы пишете сочинение, вы сначала набрасываете черновик. Зачёркиваете, переставляете абзацы, меняете слова. Это быстро и ничего не стоит. Когда черновик готов — только тогда переписываете в чистовик одним движением.

React работает так же. DOM (настоящий, в браузере) — это «чистовик»: медленный, дорогой в обновлении. Виртуальный DOM — это «черновик» в памяти JavaScript: быстрый, дешёвый. React делает все расчёты в черновике, а потом одной операцией переносит изменения в настоящий DOM.

Draft and final copy. When you write an essay, you first sketch a draft. You cross out, move paragraphs, swap words. Fast and free. When the draft is ready — only then you copy it into the final version in one motion.

React works the same way. The DOM (the real one in the browser) is the "final copy": slow, expensive to update. The virtual DOM is the "draft" in JavaScript memory: fast, cheap. React does all calculations in the draft and then in one operation pushes the changes to the real DOM.

Что происходит при клике на кнопку "+" в счётчике: [1] Клик по кнопке │ ▼ [2] React меняет данные в памяти (count = 5 → 6) │ ▼ [3] React перерисовывает виртуальный DOM (черновик) │ ▼ [4] React сравнивает старый и новый черновики │ (алгоритм называется "diffing") ▼ [5] React находит разницу: изменился только один элемент │ ▼ [6] React обновляет в настоящем DOM ТОЛЬКО этот один элемент (не трогает остальную страницу)
What happens when you click "+" in the counter: [1] Button click │ ▼ [2] React changes the data in memory (count = 5 → 6) │ ▼ [3] React re-renders the virtual DOM (draft) │ ▼ [4] React compares old and new drafts │ (the algorithm is called "diffing") ▼ [5] React finds the diff: only one element changed │ ▼ [6] React updates ONLY that one element in the real DOM (doesn't touch the rest of the page)
Итог: вам не нужно думать о DOM. Вы описываете «что должно быть», а React оптимально обновляет. Это и есть причина, почему React быстрый: он обновляет только то, что реально изменилось.
Bottom line: you don't think about the DOM. You describe "what should be", and React updates optimally. That's why React is fast: it only updates what actually changed.

5. Декларативный vs императивный подход

5. Declarative vs imperative approach

Ещё одна пара слов, которую любят спрашивать на собеседовании. Разберём на пальцах.

Another pair of words interviewers love. Let's make it simple.

Такси. Есть два способа доехать до места:

  1. Императивный: «Поверни налево. Теперь прямо 300 метров. Теперь направо у светофора. Теперь ещё прямо. Останови тут.» — вы пошагово командуете, как ехать.
  2. Декларативный: «Отвезите меня в аэропорт» — вы говорите куда, а водитель сам решает как.

«Ванильный» JS — императивный: «найди элемент, измени текст, добавь класс, удали другой элемент...». React — декларативный: «на экране должно быть вот это».

Taxi. Two ways to get somewhere:

  1. Imperative: "Turn left. Now 300 meters straight. Now right at the light. Now more straight. Stop here." — you step-by-step command how to drive.
  2. Declarative: "Take me to the airport" — you say where, and the driver figures out how.

"Vanilla" JS is imperative: "find the element, change the text, add a class, remove another element...". React is declarative: "this is what should be on screen".

Императивно (ваниль JS)
Imperative (vanilla JS)
const list = document.getElementById('list');
list.innerHTML = '';
users.forEach(user => {
    const li = document.createElement('li');
    li.textContent = user.name;
    list.appendChild(li);
});
Декларативно (React)
Declarative (React)
<ul>
  {users.map(user => (
    <li key={user.id}>{user.name}</li>
  ))}
</ul>
В декларативной версии вы описываете результат: «на экране список пользователей». В императивной — инструкции «очисти список, создай элемент, добавь в список». Декларативный код читается как схема, императивный — как инструкция сборки IKEA.
In the declarative version you describe the result: "list of users on screen". In the imperative one — instructions: "clear the list, create an element, append to the list". Declarative reads like a diagram, imperative reads like an IKEA manual.

6. SPA vs MPA: одна страница или много

6. SPA vs MPA: one page or many

Когда мы делали HTML-курс, мы создавали несколько .html-файлов: index.html, about.html, contact.html. При клике на ссылку браузер загружал новую страницу — экран мерцал, всё перезагружалось. Это MPA: Multi-Page Application, многостраничное приложение.

React-приложения устроены иначе: один HTML-файл (index.html), а все «страницы» — это компоненты, которые JavaScript показывает и прячет без перезагрузки. Это SPA: Single-Page Application, одностраничное приложение.

In the HTML course we created several .html files: index.html, about.html, contact.html. Click a link — the browser loads a new page, the screen flashes, everything reloads. That's MPA: Multi-Page Application.

React apps work differently: one HTML file (index.html), and all "pages" are components that JavaScript shows and hides without reload. That's SPA: Single-Page Application.

Откройте Gmail, нажмите на письмо, потом на «Входящие» обратно. Заметили — адрес в строке браузера меняется, но страница не перезагружается? Это SPA в действии. Gmail был одним из первых SPA в мире, ещё в 2004 году — задолго до React.

Open Gmail, click a message, then click "Inbox" back. Notice — the URL in the address bar changes, but the page doesn't reload? That's SPA in action. Gmail was one of the world's first SPAs back in 2004 — long before React.

7. Кто использует React в мире

10. Node.js и npm: что это и зачем

10. Node.js and npm: what and why

Самое частое недоразумение новичка: «Но ведь React — это же для браузера? Зачем мне что-то ставить на компьютер?» Разбираем.

The most common beginner confusion: "But React is for the browser, right? Why install something on my computer?" Let's unpack.

Что такое Node.js:

What Node.js is:

Браузер — это программа, которая умеет запускать JavaScript. Но JavaScript изначально работал только внутри браузера. Node.js — это тот же движок JS (V8 от Google Chrome), вытащенный из браузера, чтобы запускать JS как обычную программу на компьютере.

Зачем это нам? Чтобы запускать инструменты разработки: сборщик Vite, компилятор, линтер. Эти инструменты написаны на JavaScript и работают локально, на вашем компьютере, ещё до того как ваш код попадёт в браузер.

A browser is a program that runs JavaScript. But JavaScript originally worked only inside the browser. Node.js is the same JS engine (V8 from Google Chrome) pulled out of the browser so you can run JS as a regular program on your computer.

Why do we need this? To run dev tools: the Vite bundler, the compiler, the linter. These tools are written in JavaScript and run locally on your computer, before your code even reaches the browser.

Что такое npm:

What npm is:

npm = Node Package Manager. Это «магазин приложений», только для кода. Кто-то написал полезную библиотеку → опубликовал в npm → любой разработчик ставит её командой npm install package-name.

В npm сейчас больше 2 миллионов пакетов. Сам React — это npm-пакет. Vite — тоже пакет. Axios, lodash, tailwindcss — все пакеты.

npm устанавливается автоматически вместе с Node.js. Ставите Node — получаете npm. Отдельно ничего качать не нужно.

npm = Node Package Manager. It's an "app store", but for code. Someone wrote a useful library → published it to npm → any developer installs it with npm install package-name.

npm currently has over 2 million packages. React itself is an npm package. Vite — also a package. Axios, lodash, tailwindcss — all packages.

npm is installed automatically with Node.js. Install Node — you get npm. No separate download.

To create a real React project with many files you need a "starter" — a tool that generates the initial structure and configures the build. From 2013-2022 the standard was Create React App (CRA). 14. Первый React прямо в браузере (CDN)

14. First React right in the browser (CDN)

Мы обещали: первый React-код на первом занятии. Время выполнить обещание. Не будем пока лезть в npm и Vite — это на следующем занятии. Воспользуемся старым добрым способом: подключим React через <script> прямо в HTML-файл. Этот способ подходит только для учебных экспериментов и демо — но как первый шаг идеален.

We promised: first React code on the first lesson. Time to deliver. We won't dive into npm and Vite yet — that's next lesson. We'll use the good old approach: hook up React via a <script> in a plain HTML file. This approach is only good for learning and demos — but as a first step it's ideal.

Код целиком — сохраните как index.html:

Full code — save as index.html:

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>My First React</title>
</head>
<body>
    <!-- Сюда React вставит наше приложение -->
    <div id="root"></div>

    <!-- 1. Подключаем React -->
    <script crossorigin src="https://unpkg.com/react@19/umd/react.development.js"></script>
    <script crossorigin src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>

    <!-- 2. Подключаем Babel — переводит JSX в обычный JS прямо в браузере -->
    <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

    <!-- 3. Наш код. type="text/babel" важно! -->
    <script type="text/babel">
        function Hello() {
            return <h1>Привет, React!</h1>;
        }

        const root = ReactDOM.createRoot(document.getElementById('root'));
        root.render(<Hello />);
    </script>
</body>
</html>

Что тут происходит — построчно:

What's happening — line by line:

  • <div id="root"></div> — пустой контейнер. Сюда React поместит наше приложение.
  • Первые два <script> — сама библиотека React и React DOM (отдельная библиотека для работы с DOM).
  • Третий <script> — Babel. Он нужен, чтобы писать JSX (<h1>...</h1> внутри JavaScript). В реальных проектах Babel работает до отправки кода в браузер; здесь — прямо в браузере.
  • function Hello() — это компонент. Обычная JS-функция, которая возвращает JSX (то, что должно быть на экране).
  • ReactDOM.createRoot(...) — создаёт «точку входа» React в ваш #root.
  • root.render(<Hello />) — команда «покажи компонент Hello в корне».
  • <div id="root"></div> — empty container. React will place our app here.
  • First two <script>s — the React library itself and React DOM (separate library for DOM).
  • Third <script> — Babel. Needed to write JSX (<h1>...</h1> inside JavaScript). In real projects Babel runs before code reaches the browser; here — in the browser itself.
  • function Hello() — this is a component. A regular JS function that returns JSX (what should be on screen).
  • ReactDOM.createRoot(...) — creates a React "entry point" in your #root.
  • root.render(<Hello />) — command "render the Hello component into the root".

Запускаем:

  1. Создайте файл index.html в любой папке.
  2. Скопируйте код выше, сохраните.
  3. Откройте файл двойным кликом — откроется в браузере.
  4. Увидите: «Привет, React!» на странице.
  5. Откройте F12 → вкладка Components (React DevTools). Увидите компонент Hello — это доказательство, что React работает.

Run it:

  1. Create a file index.html in any folder.
  2. Copy the code above, save.
  3. Double-click the file — it opens in the browser.
  4. You'll see: "Привет, React!" on the page.
  5. Press F12 → Components tab (React DevTools). You'll see the Hello component — proof React is running.

Привет, React!

Поздравляем! Это настоящий React. Тот же, что на Instagram и Netflix. Различие только в упаковке: реальные проекты собирают в оптимизированный бандл через Vite. Суть — та же.
Congratulations! This is real React. The same one as on Instagram and Netflix. The only difference is packaging: real projects bundle it optimally via Vite. The essence is the same.

CDN-подход годится только для учёбы и быстрых демо. В настоящих проектах так писать нельзя:

  • Babel в браузере — медленно (замедляет загрузку в 5-10 раз)
  • Нет оптимизации (размер файла большой)
  • Нет разделения на файлы — всё в одном HTML, каша
  • Подключение development.js — это дебажная версия, не для продакшена

Для реальных проектов — только Vite (научимся на занятии 2).

CDN approach is only for learning and quick demos. You can't write real projects this way:

  • Babel in the browser — slow (5-10× slower load)
  • No optimization (big file size)
  • No file splitting — everything in one HTML, a mess
  • development.js is the dev build — not for production

For real projects — Vite only (learning on lesson 2).

  8. Инструменты: Node.js 22 LTS, VS Code + 4 расширения, React DevTools

  10. В 2026 все новые проекты — на Vite (CRA устарел)
  11. React подключается через CDN за 3 строки (учебный способ)
